# Security

Use GitHub’s [private vulnerability reporting](https://github.com/rnepal2/metricairn/security/advisories/new) for security issues. If unavailable, contact the owner privately through an existing channel. Never put credentials or identifiable event payloads in public issues. Fixes target the latest main branch; there is no managed-service SLA.

- Tracking keys collect events. Read keys disclose one project’s analytics. Management keys configure, rotate credentials, save/review evidence, and delete data. Treat read and management keys as secrets.
- Project creation is open when `PROVISIONING_TOKEN` is empty. Set it before network exposure. This does not replace user authentication.
- MCP defaults to read-only tools. HTTP mode binds to loopback and has no public authentication; do not expose it through a tunnel.
- SQL generated by an optional provider uses a function allowlist, enforced tenant/time boundaries, read-only execution, cancellation, and row limits. Never expose internal execution helpers directly.
- Body/property limits are implemented; application rate limiting is not. Public installations need TLS, operator-controlled request limits, backups, and restricted administrative access.
- Browser identifiers, custom properties, and question history can contain personal data. Query cleanup and privacy controls do not anonymize arbitrary payloads. Minimize collection and choose appropriate retention/consent policies.

Optional delivery providers receive alert/digest contents; optional AI providers receive schema, questions, project identifiers, and date ranges. Existing Stripe support is deployment-owned and is not a multi-customer payment service. See [operations](docs/operations.md).
